# What is a Spark job?

A Spark Job is a unit of execution triggered when an action is called on an RDD, DataFrame, or Dataset in Apache Spark.

A Spark job consists of one or more stages, and each stage consists of multiple tasks that execute in parallel across the cluster.

## 1. How is a Spark Job created?

Spark uses lazy evaluation, meaning transformations are not executed immediately. Instead, Spark builds a logical execution plan and starts executing it when an action is triggered.

```python
df = spark.read.parquet("s3://bucket/sales/")
filtered_df = df.filter(df.amount > 1000)           # Transformation
grouped_df = filtered_df.groupBy("region").count() # Transformation

grouped_df.show()  # Action: triggers Spark job execution
```

In this example:

- `read.parquet()` defines the input DataFrame.
- `filter()` and `groupBy()` define transformations.
- `show()` is an action that triggers execution.
- Spark creates one or more jobs to execute the required computation.

Important: One action typically triggers one Spark job, but a single action can trigger multiple jobs depending on the execution plan, such as when Spark runs separate work for broadcast exchanges or other internal operations.

## 3. Difference Between Job, Stage, and Task

| Component | Description | Created by |
| --- | --- | --- |
| Job | Complete computation initiated by an action | Spark execution machinery |
| Stage | Group of tasks that can run without requiring a shuffle between them | DAG Scheduler |
| Task | Smallest unit of execution, typically processing one partition | Task Scheduler schedules tasks |

## 4. Can One Spark Application Have Multiple Jobs?

Yes. A single Spark application can execute multiple jobs.

```python
df = spark.read.parquet("s3://bucket/sales/")

df.count()  # Action 1: job(s)
df.show()   # Action 2: job(s)

# Action 3: job(s)
df.write.mode("overwrite").parquet("s3://output/")
```

Each action triggers execution, potentially generating one or more Spark jobs.

## 5. Interview-ready Answer

> A Spark job is a unit of computation triggered by an action such as `count()`, `collect()`, or `show()`. When an action is executed, Spark uses the execution plan to schedule one or more jobs. The DAG Scheduler divides each job into stages based on shuffle dependencies, and each stage contains tasks that execute in parallel on executor cores. A single Spark application can contain multiple jobs, and one action may sometimes trigger multiple jobs.

Key point to remember: Application → Jobs → Stages → Tasks

- Action triggers job execution.
- Shuffle boundaries generally determine stage boundaries.
- Partitions generally determine the number of tasks in each stage.
