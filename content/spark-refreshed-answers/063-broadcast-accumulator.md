# What is the difference between a broadcast variable and an accumulator?

In Apache Spark, broadcast variables and accumulators are shared-variable mechanisms, but they serve opposite purposes.

- **Broadcast variable:** Used to distribute read-only data from the driver to executors efficiently.
- **Accumulator:** Used to aggregate values from tasks running on executors back to the driver.

## 1. Key differences

| Feature | Broadcast variable | Accumulator |
| --- | --- | --- |
| Purpose | Share data across executors | Aggregate values from tasks |
| Data flow | Driver → Executors | Executors → Driver |
| Modification | Read-only | Tasks can add values |
| Read access | Driver and executors | Global value read on the driver; PySpark tasks cannot read `.value` |
| Typical use cases | Lookup tables, configuration | Counters, metrics, debugging |
| API | `sc.broadcast()` | `sc.accumulator()` |
| Aggregation | No | Yes |
| Fault tolerance | Data can be fetched again | Task updates may be affected by retries and recomputation |

## 3. Broadcast variable example

Suppose you want to share country-code mappings across multiple Spark tasks.

```python
country_map = {
    "IN": "India",
    "US": "United States",
    "UK": "United Kingdom"
}
broadcast_map = sc.broadcast(country_map)
rdd = sc.parallelize(["IN", "US", "UK"])

result = rdd.map(lambda x: broadcast_map.value.get(x))
print(result.collect())
```

Output:

```text
['India', 'United States', 'United Kingdom']
```

Here, executors can access the read-only dictionary efficiently. PySpark workers may each deserialize their own copy.

## 4. Accumulator example

Suppose you're processing millions of records and want to count invalid records.

```python
invalid_count = sc.accumulator(0)
rdd = sc.parallelize([10, -5, 20, -3, 40])

def validate(x):
    if x < 0:
        invalid_count.add(1)
    return x

result = rdd.map(validate)
result.collect()
print(invalid_count.value)
```

Output for this simple execution without recomputation:

```text
2
```

### What happens internally?

1. Driver creates an accumulator initialized to zero.
2. Tasks running on executors increment their accumulator updates.
3. Spark communicates task updates back to the driver.
4. The driver aggregates these updates into the final count.

Accumulators are suitable for metrics, not critical application logic. Updates inside transformations such as this `map()` may be applied more than once during retries or recomputation, and repeated actions can increase the count again. Updates performed directly inside actions have stronger retry handling: Spark applies each task's update once for that action.

For an exact business result, use a distributed aggregation such as `rdd.filter(lambda x: x < 0).count()`.

## 5. Important interview scenario

Suppose you have a Spark job processing 100 million transactions.

You need to:

- Share a dictionary of 5,000 currency codes and configuration mappings across all tasks.
- Count the number of invalid transactions detected during processing.

Solution:

- Use a broadcast variable to share the reference dictionary.
- Use an accumulator to count invalid transactions as a processing metric.

This avoids repeatedly distributing reference data while enabling centralized collection of processing metrics.

## 6. Can an accumulator replace a broadcast variable?

No. They have fundamentally different responsibilities.

An accumulator is not a general shared mutable variable. Executors can contribute updates, but tasks cannot use its aggregated global value to coordinate computation.

Similarly, broadcast variables cannot be used to collect results or updates from executors.

## Interview-ready answer

> Broadcast variables and accumulators are both shared-variable mechanisms in Spark, but they serve different purposes.

> A broadcast variable distributes read-only data from the driver to executors efficiently, allowing tasks to reuse it.

> An accumulator aggregates values generated by executor tasks back to the driver, typically for counters, debugging, or monitoring metrics.

> For example, I would use a broadcast variable to share a lookup dictionary across executors, while using an accumulator to count invalid records during data processing.

**Key takeaway:** Broadcast variables are for distributing data, while accumulators are for collecting aggregated updates.
